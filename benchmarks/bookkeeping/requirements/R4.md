# R4 · 记账操作者与账户记账历史

## 给智能体的需求

### 业务需求

转账可以标识**发起者**，即操作者，例如用户标识或服务名称。

- 操作者是可选的。未指定操作者的转账保持原有行为，生成的记账记录不携带操作者。
- 指定操作者时，将其记录在生成的记账记录中，并支持读取。
- 账本可以列出指定账户的记账记录，每条记录包含交易引用、交易类型、时间戳和操作者；未指定操作者时为 `null`。
- 操作者属于持久化记账信息，从任意存储后端重新加载后仍须保留，并返回相同的值。
- 记录操作者不改变金额、余额或记账记录数量。

### 公共 API 要求

```java
// 所在类型：com.yanimetaxas.bookkeeping.model.TransactionRequest / TransferRequest
public String getActor();

// 所在类型：com.yanimetaxas.bookkeeping.model.Transaction
public String getActor();

// 新类型所在包：com.yanimetaxas.bookkeeping.model
public final class AccountPosting {
    public AccountPosting(String transactionRef, String transactionType, Money amount, String actor, Instant timestamp);
    public String getTransactionRef();
    public String getTransactionType();
    public Money getAmount();
    public String getActor();
    public Instant getTimestamp();
}
```

```java
// 新类型所在包：com.yanimetaxas.bookkeeping.service
public interface PostingHistoryService {
    List<AccountPosting> listPostings(String accountRef);
}
```

必须能够从账本获得历史查询服务，且该服务只返回所属账本的记账记录。

转账请求还必须支持指定操作者。未指定操作者的调用者仍可完全按原方式使用现有分阶段构建器。
在给定金额后的任意阶段均可指定操作者；从未指定时，读取结果为 `null`。

### 验收标准

1. 指定操作者后提交转账，生成的记账记录中的操作者等于传入值。
2. 未指定操作者时，记账记录中的操作者为 `null`，转账仍按原行为成功。
3. `listPostings` 对每笔涉及该账户的转账返回一条记录，按提交顺序排列，并包含正确的引用、类型、金额和操作者。
4. 从未发生记账的账户调用 `listPostings` 返回空列表。
5. 操作者在重新加载后保留：使用同一后端重新打开账本后，`listPostings` 仍返回相同的操作者。
6. 记录操作者不改变任何余额。
7. 所有存储后端行为一致，扩展现有跨后端契约测试以覆盖此需求。

## 中文说明（不给 Agent）

**业务场景**：审计追溯 —— 每一笔记账是谁做的。当前 A 的 `Transaction` 只有 reference / type / 时间戳，**没有操作者**，
所以「谁记的账」这个信息在系统里根本不存在。这是典型的「可修改性」问题：
**信息没有被建模，后续想加审计就要改动存储 schema、DTO、两套后端的映射**。

**为什么这条需求特别有价值**：它要求新增一个**需要持久化的字段**。
在 A 上，字段要加到 `Transaction`（model）、`TransactionRequest`、内存版的存储结构、JDBC 版的表结构与映射 —— 每处都是一处改动；
且 model ↔ validation / model ↔ report 已成环，新增字段容易把环加深。

## 预期架构敏感点（不给 Agent）

| A 的弱点 | 预期在 A 上放大的成本 |
|---|---|
| `Transaction` 双后端映射（内存结构 + JDBC schema/mapper） | 新字段要加到 2 套存储表示 + 2 套映射 |
| `model ↔ report` / `model ↔ validation` 循环 | 新结果类型 `AccountPosting` 放哪都会牵扯这两个环 |
| `TransferRequest` 分阶段 Builder（公共接口） | 加 actor 要动一串 公共接口，且不能破坏既有调用方式 |
| `getTransactionRefsForAccount` 等查询规则双后端实现 | 历史查询要接线两套后端 |
